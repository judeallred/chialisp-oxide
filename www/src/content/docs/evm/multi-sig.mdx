## Approvals are signatures on one spend

The contract keeps a list of transactions and a confirmation count in storage,
and each owner calls `confirmTransaction` in a separate transaction before
anyone calls `executeTransaction`.

The Chia version needs no stored votes. One spend returns two `AGG_SIG_ME`
conditions, one per signer, over the same coin-bound message. The signers
combine their signatures off chain into one aggregate, and consensus checks both
in the same transaction. A spend with only one signature is rejected by
consensus.

This export is a fixed 2-of-2 policy with both keys named in the puzzle. A
general m-of-n policy with changeable owners is not in the corpus yet.
