## What this means

- **In-block deduplication already exists.** The pinned `chia-consensus` 0.36.1
  deserializes block generators with CLVM backreferences, so a module repeated
  within one block can be serialized once. The large within-block share shows
  that matters, but this range’s generators were only lightly compressed.
- **Solutions are the bigger target.** Standard-puzzle solutions carry their
  delegated condition programs, and they make up most spend bytes here. A
  cross-block “module by hash” reference could remove at most the repeated
  module share of reveal bytes, which are a small fraction of the total.
- **The cross-block number is a projection.** No such reference exists in
  consensus. It would need a CHIP, a canonical module registry (overlapping
  [#21](https://github.com/judeallred/chialisp-oxide/issues/21)), and node
  storage and validation work.

One recent range is not a trend over time, the provider’s responses are not
authenticated here, and only the outermost curried module is uncurried.
