**WIP prototype. Not ready for use with funds or production puzzles.**

Optimizing a puzzle means reducing its cost in a real transaction context.
Raw module size and VM execution are useful diagnostics, but generator
serialization can change which optimization matters most. This experiment
executes both uncompressed and backreference generators for exact signed bundles
already admitted by the SDK simulator.

Start with [delegated conditions](/chialisp-oxide/tutorials/delegated-conditions/)
or [pay-to-singleton composition](/chialisp-oxide/tutorials/p2-singleton/) for
the policies and their independent Chialisp, Rust and Rue sources. The
[earlier transaction-cost lesson](/chialisp-oxide/tutorials/transaction-costs/)
retains a historical source-only checkpoint; the measurements below bind the
current corpus instead.

## Read each cost in its own context

The pinned `get_conditions_from_spendbundle` helper executes the puzzles and
conditions, skips signature verification, and charges the uncompressed
generator length minus its two-byte quote wrapper.

The pinned `run_block_generator2` API executes an actual generator and verifies
its aggregate signature. With no block references, this quoted generator adds
20 VM cost and charges every byte of the supplied encoding. Both uncompressed
and backreference encodings must expand to exactly the same tree. Each cost is:

```text
total = execution cost + condition cost + serialized-byte charge
generator byte charge = actual generator length × 12,000
```

The 12,000 multiplier and these API rules belong to this exact pre-hard-fork-2
TESTNET11 configuration (`chia-consensus 0.36.1`, `clvmr 0.16.2`). They are
resource units, not a fee quote, wall-clock measurement or prediction for every
network, fork or generator construction. Signature verification is enabled in
the generator runs; no separate BLS execution-cost component is added here.

## Compare the complete generators

<GeneratorCosts />

The ordinary owner-signed delegated Rust spend uses 500 backreference bytes,
versus 293 for Chialisp. Their generator execution differs by 10,501 units,
while the byte charge differs by 2,484,000. That makes repeated program
structure and remaining call/constructor frames concrete optimization targets.
This observation concerns this input; other conditions trees can change the
execution work and serialization.

A backreference encoding can be especially helpful for a large unoptimized
program. This does not make an unoptimized program the preferred compiler
output: compare the actual total cost in the relevant column. Shrinking a raw
program that already compresses well may save very little in that column.

## Reproduce all selected bundles

The reusable experiment selects 35 exact bundles through JSON pointers in
`experiments/spend-costs/cases.json`: four delegated scenarios and three
singleton lifecycle phases, each in all five builds. It includes the unsafe
uncurried key-selection successes as explicitly named policy counterexamples.
Those successes do not establish a safe ownership policy.

From the repository root, after the [Cargo setup](/chialisp-oxide/start/quickstart/):

```sh
cargo build --manifest-path experiments/spend-costs/Cargo.toml --locked
python3 experiments/spend-costs/check.py --self-test \
  --execute experiments/spend-costs/target/debug/chialisp-oxide-spend-costs \
  --output target/generator-cost-execution
```

Choose a new output directory for each run. This first validates the current
corpus, then executes 35 conditions-helper calls and 70 baseline generator
calls. It also executes 140 exact `BadAggregateSignature` controls using
identity and unrelated valid nonempty signatures, plus 70 resource-boundary
pairs: the measured total succeeds as an exact budget, and one unit less fails
with `CostExceeded`. Resource failures add no policy-rejection credit. These
are finite checks of the selected bundles, not exhaustive cryptographic tests.

Exact selected transactions, generated bytes, logs and a binary-hash receipt
remain in the output directory. The checker independently reconstructs each
uncompressed generator, decodes backreferences with a bounded reference codec,
compares the trees, and checks cost arithmetic. It requires a quiet source,
input and binary window and exact agreement with the committed measurements.
Adding a port extends the case data and does not require another per-port
benchmark implementation.

Running the checker without `--execute` checks only recorded consistency and
source freshness. Its corruption controls do not execute the VM. Recorded
Booleans and hashes do not authenticate a past run or installed dependency
bytes.

## Keep the ledger boundary visible

Generator execution verifies conditions and aggregate signatures. It does not
reconstruct coin-store existence, spent state, birth heights or the whole
ledger. The original simulator admissions and exact typed rollback checks
remain separate evidence, and these measurements add no new SDK admissions.
The raw laboratory still uses `clvmr 0.21.0`, a different context from this
experiment. None of these checks proves compiler preservation, exhaustive
authorization, production readiness or puzzle security.
