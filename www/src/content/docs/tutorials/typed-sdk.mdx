Two 32-byte values can mean different things. A recipient puzzle hash and a
spent coin ID have the same byte length, but passing one where the other is
required can encode the wrong policy. Similarly, both an amount and an absolute
timestamp fit in `u64` without being interchangeable concepts.

The source-only SDK uses Rust's nominal types to make these distinctions at
helper call sites. The compiler supports a narrow transparent-wrapper form and
erases each wrapper to its inner wire representation after Rust checking.

## Use the actual capped-payment fixture

<SourcePair slug="capped-payment" />

The source file includes `sdk/oxide.rs` with a Rust `#[path]` module attribute.
From `puzzles/capped-payment/puzzle.rs`, `../../sdk/oxide.rs` resolves to the
repository's source-only module. This is local code compiled with the puzzle,
not an external on-chain Rust library or an installed SDK package.

The entrypoint accepts an `Amount`. Reading `amount.0` obtains the inner `u64`
for the cap check. `assert_my_amount` returns the input-amount condition, and
`create_coin` requires a `PuzzleHash` and an `Amount` for its arguments.

```sh
./scripts/oxide build puzzles/capped-payment/puzzle.rs --output target/typed-cap
./scripts/oxide run target/typed-cap.clvm.hex --solution '(500)' --max-cost 1000000
```

The accepted solution remains `(500)`. It does not become `((500))`, and it
does not carry an `Amount` tag. The compiled fixture still has the same cap,
fixed destination, permissionless amount choice, and remainder-as-fee policy.


The test `rustc_rejects_domain_swaps_before_ir_lowering` checks the error code,
both domain names, and the absence of emitted IR. Run the complete feature
regressions with:

```sh
cargo test -p oxide-driver --test newtypes --locked
```

This protection is meaningful at the typed Rust API boundary. Rue's nominal
struct types can express analogous domain distinctions; the example does not
claim this capability is unique to Rust.

## Inspect the small SDK

<SdkSource />

`PuzzleHash`, `CoinId`, `PublicKey`, and `Message32` wrap fixed-size bytes.
`Amount` and `Timestamp` wrap `u64`. Named helpers supply the four condition
codes used here. Their result aliases remain tuples, not a closed nominal
`Condition` enum: callers can still construct raw tuples manually.

The wrappers deliberately expose their fields. An explicit unwrap and rewrap,
such as `PuzzleHash(coin.0)`, can bypass the source-level domain distinction.
The compiler prevents an accidental direct mismatch; it does not establish
that any supplied bytes are the intended puzzle hash or key.

Amounts remain ordinary duplicable numeric values: their inner `u64` can be
copied and wrapped again. Rust's move checks do not enforce money conservation
or prevent double spends. Those remain explicit consensus and ledger-test
obligations.

## What the feature does not validate

ABI decoding does not call a wrapper constructor or a custom validation
function. A `PuzzleHash` argument receives an atom of exactly 32 bytes;
it does not prove that the bytes identify the intended puzzle. An `Amount`
argument receives a canonical in-range `u64`; it does not acquire the
application's cap or a conservation invariant just from its name. Keep those
assertions in the puzzle body and check coin context with consensus conditions.

No runtime domain tags are added. An attacker who supplies a coin ID's bytes
in a `PuzzleHash` argument position can satisfy the length check. Source types
and untrusted wire values have different trust boundaries.

## Supported layouts and executed tests

Only local, nongeneric, non-macro-generated `#[repr(transparent)]` structs with
exactly one field, a supported nonzero-size inner type, and no custom `Drop`
are accepted. Nested supported wrappers can erase recursively. General
structs and enums remain unsupported. Even an additional zero-size field is
outside this deliberately narrow form.

The feature tests reject eight unsupported declaration/layout forms, preserve
the bytes32 ABI through nominal round trips, compare SDK helper results with
native execution and independently compiled Chialisp, check malformed inputs
in both optimization modes, and exercise nested wrappers. The nine-puzzle
corpus separately validates the SDK-backed capped payment. Read its actual
[case and ledger evidence](/chialisp-oxide/lab/capped-payment/) rather than
treating a nominal type as an authorization or security proof.
