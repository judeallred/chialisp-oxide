The bounded counter is deliberately a pure function. It returns an integer,
not conditions, so it is not submitted as a coin puzzle. This makes it a small
example for studying arithmetic and model-level reasoning.

## Distinguish policy from width

For canonical `u64` input below 1,000, the result is input plus one and lies in
`1..=1000`. Input 1,000 rejects because of the policy guard. A large input also
must obey the `u64` boundary and checked-addition semantics; CLVM's unbounded
integers cannot replace those obligations.

`COUNTER_LIMIT` names the policy boundary. The increment of one remains an
explicit arithmetic operation; neither that name nor a domain wrapper changes
the checked `u64` semantics.

The optimizer can also use the successful guard: `counter` is then in
`0..=999`, so its increment fits in `u64`. The current interval pass uses this
fact to remove one discarded, repeated checked-arithmetic initializer from
the extracted IR. It keeps the final checked addition, complete decoder and
policy assertion. Input 1,000 still rejects, and padded input `0x0001` never
reaches the body. See the [measured interval and decoder changes](/chialisp-oxide/reference/optimization/)
for actual before/after bytes, VM costs and the distinct model-proof boundary.

The generated corpus sweep exercises values on both sides of the policy
boundary. This is finite test evidence. The formal companion instead asks a
solver to find a violation of explicit predicates over the source-derived IR.

## Make the specification independent

The range specification requires output between 1 and 1,000 and equal to input
plus one on success. The acceptance specification requires success exactly
when the typed input is below 1,000. Merely copying the implementation into an
assertion would make a weaker test of the intended policy.

The formal report includes a satisfying input to show the obligations are not
vacuous, then replays witnesses in native Rust and both CLVM modes. It also
removes the outer policy guard while retaining checked increment. The resulting
counterexample must be caught and replayed.

Read [the formal evidence](/chialisp-oxide/verification/formal/) for the exact
current witness and scope. The solver proves properties of its IR model; these
checks do not prove the compiler, ABI decoder, optimizer, or all puzzle security.

The [counter lab](/chialisp-oxide/lab/bounded-counter/) shows the corresponding
finite cases, generated sweep count, compiled programs, and measured costs.
