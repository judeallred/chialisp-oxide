Every solution is an attacker-controlled CLVM tree. A Rust signature describes
the accepted boundary values; it does not make raw CLVM input trusted. The
default ABI validates the complete solution shape and parameter encodings before
evaluating the function body. A separately declared ignored-environment mode is
restricted to parameterless exports.

## Explicit raw-tree environments

`#[chialisp_oxide::puzzle(environment = "raw")]` passes the **entire** environment
to one borrowed `Tree` parameter. It adds no argument-list, numeric-canonicality,
or tail check. `Tree::Atom(&[u8])` preserves arbitrary atom bytes;
`Tree::Pair(&Tree, &Tree)` preserves proper and improper pairs. Pattern matching
can require a pair, bind its children, or accept an atom. Failed projections
reject; pair construction evaluates both children strictly.

The [canonical p2_conditions port](/chialisp-oxide/tutorials/p2-conditions/)
uses this contract: `(5 . 99)` supplies one environment tree, rather than failing
a single-argument-list decoder. Its function requires the environment to be a
pair, takes its first child and deliberately ignores its rest. The produced
program `(1 . 5)` returns `5` when subsequently executed.

This is an explicit policy choice. Raw bytes are not validated amounts, hashes,
conditions or programs. The default typed ABI retains its full checks. The raw
policy uses IR envelope version 3 when no runtime constructs are present;
ignored nullary exports then use version 2, and strict programs retain their
original wire format. Runtime programs use version 4 without changing those
input policies. A legacy reader cannot silently interpret the raw policy as a
typed argument list.

## Function arguments form a proper list

For a single `Amount` or `u64` parameter, the solution is `(42)`,
not the bare atom `42`, the pair `(42 . 1)`, or a list
with extra arguments. By default, a zero-argument function takes `()`. Missing arguments,
improper tails, nested pairs in scalar positions, and additional arguments reject.

## Explicitly ignored environments

`#[chialisp_oxide::puzzle(environment = "ignored")]` opts a parameterless
export into accepting any CLVM tree without decoding arguments or imposing a
proper-list shape. It is not available for functions with parameters. The
default `#[chialisp_oxide::puzzle]` contract is unchanged.

The three [canonical Intro expressions](/chialisp-oxide/tutorials/canonical-intro/)
use this mode because their original Chialisp programs ignore the environment.
Both `()` and `(1 . 2)` therefore reach the same closed function. Malformed
serialized CLVM and VM resource limits still apply; ignoring a tree does not
make it a typed Rust argument. The payment puzzles retain strict argument
validation, including their nullary `()` requirement where applicable.

## IR version 4 and export markers

Runtime calls add an internal wire version, not another authoring attribute.
The existing `#[chialisp_oxide::puzzle]` marker selects strict arguments;
`environment = "ignored"` selects a nullary function, and `environment = "raw"`
selects one complete tree. Their metadata markers remain respectively
`__oxide_puzzle_v1`, `__chialisp_oxide_puzzle_v2_environment_ignored`, and
`__chialisp_oxide_puzzle_v3_environment_raw`. No `environment = "runtime"` or
version-4 macro marker exists.

A function table or any `Call`, `Let`, or `Local` requires this envelope:

```json
{
  "ir_version": 4,
  "environment": "strict",
  "program": {
    "name": "wire-example",
    "parameters": [],
    "result": { "kind": "unit" },
    "body": { "op": "call", "function_id": 0, "arguments": [] },
    "functions": [
      {
        "id": 0,
        "name": "helper",
        "parameters": [],
        "result": { "kind": "unit" },
        "body": { "op": "unit" }
      }
    ]
  }
}
```

This is a wire illustration. Function IDs must equal their table positions.
Each function has its own parameter and lexical-local scopes. A `Let` carries
an explicit type, evaluates its initializer once before its body, and checks the
initializer outside the new binding. Calls evaluate arguments once, left to
right; a callee receives no caller locals. The table and runtime slots are
compiler internals and add no wrapper to the submitted solution or returned
value. Strict external decoding still checks every argument, even when unused,
before entering the runtime frame. Ignored/raw inputs retain their contracts.

Legacy v1/v2/v3 documents cannot contain these nodes, including inside an
unchosen branch. Runtime-free programs keep their existing serialization.
A v4 envelope must contain a runtime node or a nonempty function table;
`functions: []` with a legacy-only body is invalid, so decoding cannot silently
downgrade an explicitly versioned request to legacy semantics.
Current scalar and structural SMT models reject runtime IR even if its table is
unused; finite VM replay is a separate execution check. See
[compiler architecture](/chialisp-oxide/reference/architecture/#closed-runtime-functions).

## Integers are canonical signed atoms with declared bounds

CLVM atoms represent integers in signed big-endian two's complement. The ABI
requires the shortest canonical encoding and the Rust type's numeric range.
Numeric zero is the empty atom `()`. Positive 128 needs a leading zero byte to
avoid becoming negative; positive one does not.

- `1` is accepted for `u64`.
- `0x0001` rejects as padded, even though CLVM arithmetic can treat it as one.
- `-1` rejects for an unsigned parameter.
- `18446744073709551616` rejects for `u64`.
- A pair rejects before numeric operations inspect it.

Signed parameters preserve signed bounds. Arithmetic uses those same declared
bounds and rejects on overflow. The VM's arbitrary-precision arithmetic is an
implementation mechanism, not permission to change Rust integer semantics.

The optimized integer decoder uses a lazy nil case and unsigned byte bounds
`[0080, ff80)` for nonempty minimal signed encodings. It retains atom shape,
length and numeric-width checks before running the body. The separate
[canonicality law](/chialisp-oxide/reference/optimization/#decode-canonical-integers-without-repeating-the-body)
is a Seq8 model with source-hash metadata, not a translation proof of this ABI.

## Booleans, bytes, and products

A boolean accepts exactly `()` or `1`; other truthy atoms such as `2` reject.
A `[u8; 32]` parameter is one atom containing exactly 32 bytes, not a list of 32
numeric atoms. Fixed-byte encodings are byte strings, so leading zeros are
meaningful and are not subject to numeric canonicalization.

Tuples are proper lists whose fields are recursively validated. Unit is the
empty list. These are explicit logical layouts, independent of Rust memory
layout, alignment, or endianness.

## Explicit pairs with `Cons<Head, Tail>`

Tuples keep their proper-list encoding. The vetted facade also provides
`chialisp_oxide::Cons<Head, Tail>` for an explicit CLVM pair `(head . tail)`.
Both fields have supported concrete types; the tail need not be a list. This
is a wire declaration, independent of Rust memory layout.

The actual Cargo frontend tests include this ordinary Rust export:

```rust
use chialisp_oxide::Cons;

#[chialisp_oxide::puzzle]
pub fn head(value: Cons<u8, u8>) -> u8 {
    value.first
}
```

Its default solution is `((99 . 8))`: one argument whose value is a pair.
`((99 8))` rejects because its tail is a list, not a `u8` atom. An out-of-range
or padded tail still rejects even though the body only reads the first field.
A `Cons` constructor evaluates both fields once in source order, including a
strict initializer that is later unused.

A tail typed as `Tree` retains exact atom bytes and improper pairs. A raw export
still takes the whole environment as one logical `Tree`; returning `Cons` does
not add an argument-list wrapper or validate ignored input tails. The frontend
checks the actual SDK declaration and concrete types. A similarly named local
struct, arbitrary generic function, custom layout or unrelated external type
does not receive this encoding.

Typed Pair capability uses the explicit **version-5 IR envelope**, with the same
`strict`, `raw` and ignored-environment contracts. Older wire versions reject
Pair types and expressions, including in an unused function signature. This is
separate from `Tree::Pair`, which represents an arbitrary borrowed input tree.
Current scalar, structural and acyclic SMT models reject typed wire Pair
capability; successful frontend/native/VM tests are not a model theorem or a
compiler-preservation proof. These tests are not extra corpus puzzles or spends.

## Nominal wrappers erase to the inner encoding

A supported local or vetted SDK single-field `#[repr(transparent)]` wrapper preserves Rust's
source-level type identity but adds no CLVM wrapper node or domain tag.
`PuzzleHash([u8; 32])` is the same 32-byte atom as its inner array; `Amount(u64)`
is the same canonical numeric atom as its inner integer. A one-argument
`puzzle(amount: Amount)` therefore takes `(500)`, not `((500))`.

ABI decoding does not run a Rust constructor or custom validator. It enforces
the erased inner type's encoding, length, and range, not a domain-specific
invariant. A correctly sized atom is not proof that its bytes name the intended
puzzle. Keep policy assertions and authorization checks explicit. Nested
supported wrappers erase recursively; general structs and enums remain
unsupported. See the [typed SDK tutorial](/chialisp-oxide/tutorials/typed-sdk/)
for supported declarations and observed compile-fail diagnostics.

through typed helpers:

At the wire level, the result is a proper list containing `(73 1000)` and
`(51 0x4242…4242 1000)`. Those are `ASSERT_MY_AMOUNT` and `CREATE_COIN` conditions.
The repeated destination bytes describe the recipient puzzle hash, not an
address string.

The real `chialisp-oxide` crate provides nominal `Amount`, `PuzzleHash`, `CoinId`,
`PublicKey`, `Message32`, and `Timestamp` wrappers with named condition helpers.
The consumer and `chialisp-oxide-puzzles` corpus both depend on that crate. Standalone
frontend regression fixtures can still use the compatibility module, but it is
not the corpus route. These payment aliases remain tuples even though the examples use
named constructors. The explicit `Cons<Head, Tail>` exception instead preserves a pair
and its independent tail, as the [delegated-conditions lesson](/chialisp-oxide/tutorials/delegated-conditions/) shows. `Amount::from_mojos` and `Timestamp::from_unix_seconds`
make units explicit without changing these wire representations.
There is no closed nominal `Condition` enum: an incorrect manually constructed
opcode can still compile. The [condition reference](/chialisp-oxide/reference/conditions/)
and simulator tests remain necessary policy checks.
