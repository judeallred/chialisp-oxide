## From a Rust function to a simulated coin spend

Rust handles names, types, and borrow checks. Oxide lowers a deliberately small
subset of checked MIR into a pure IR. Rue optimizes the result and emits CLVM.
Independent Chialisp references and a ledger simulator make the result inspectable.

## Errors rejected before CLVM generation

- Passing a `CoinId` directly to the SDK's `create_coin`, which requires a
  `PuzzleHash`.
- Passing an `Amount` directly to `assert_seconds_absolute`, which requires a
  `Timestamp`.
- Mixing incompatible primitive types, such as adding `true` to a `u64`.

These cases are executable compile-fail regressions. The domain protections
apply at named SDK call sites; public fields still permit explicit unwrap and
rewrap. Rue can express analogous nominal distinctions. [Run the actual SDK
examples](/chialisp-oxide/tutorials/typed-sdk/) and read the [full error
study](/chialisp-oxide/verification/error-study/) for the remaining runtime and
policy obligations.

## Experimental evidence has limits

The current compiler is an experimental subset, not a general Rust target or an
audited wallet. The lab exposes measured evidence and the remaining assumptions.
Formal models are labeled separately from end-to-end compiler proofs. Canonical
CHIP module hashes remain compatibility requirements, even when tests agree.

Start with [what works today](/chialisp-oxide/reference/supported-rust/), then read
[the validation method](/chialisp-oxide/verification/method/) before extending a puzzle.
