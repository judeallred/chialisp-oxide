## From a Rust function to a simulated coin spend

Rust handles names, types, and borrow checks. chialisp-oxide lowers a deliberately small
subset of checked MIR into a pure IR. Rue optimizes the result and emits CLVM.
Independent Chialisp and Rue source compilations, plus a ledger simulator, make the result inspectable.

<div className="pipeline" aria-label="Compiler pipeline">

## Errors that Rust makes impossible

These faulty Chialisp examples pass deliberately limited tests that assert exact
outputs. A distinguishing input exposes each bug. The corresponding Rust source
mistakes fail type or name checking before they can become CLVM.

## Published puzzles and functionality gaps

[Browse the published-source catalog](/chialisp-oxide/published/) to discover
pinned Chialisp, Rue, and Rust files across official and community repositories.
Discovery, working translations, and validated coin behavior remain separate.

[The functionality map](/chialisp-oxide/reference/chialisp-functionality/)
shows what this compiler supports and what remains missing. General Rust
expressibility is not a proof of compiler parity. Dynamic trees, unbounded
integers, recursion, hashing and crypto, currying, and runtime program evaluation
remain explicit backend work.

## Experimental evidence has limits

The current compiler is an experimental subset, not a general Rust target or an
audited wallet. The lab exposes measured evidence and the remaining assumptions.
Formal models are labeled separately from end-to-end compiler proofs. Canonical
CHIP module hashes remain compatibility requirements, even when tests agree.

Start with [what works today](/chialisp-oxide/reference/supported-rust/), then read
[the validation method](/chialisp-oxide/verification/method/) before extending a puzzle.
