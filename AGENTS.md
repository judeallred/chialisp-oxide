# Working on chialisp-oxide

Build toward goals.md; record current capabilities and gaps without shrinking the goals.
Use docs/compiler-approach.md for architectural context and docs/verification.md for claim scope.

- Keep the public facade named `chialisp-oxide` (Rust import `chialisp_oxide`), companion packages `chialisp-oxide-*`, and the Cargo executable `cargo-chialisp-oxide` (`cargo chialisp-oxide`). Re-export puzzle macros through the facade so consumers do not depend directly on the proc-macro crate. All project crates remain unpublished; use path dependencies or reviewed pinned Git revisions.
- The source language is real Rust checked by rustc. Never substitute textual MIR parsing or a Rust-looking DSL while claiming Rust semantics.
- Keep rustc internals in chialisp-oxide-driver and Rue internals in chialisp-oxide-ir/backend adapters.
- Reject unsupported constructs with useful diagnostics. Preserve strict failure behavior, integer width/overflow rules, and exact ABI validation.
- Treat all solutions as attacker-controlled CLVM trees. Test malformed shapes, padded numbers, oversized values, authorization failures, and optimization on/off.
- Differential tests must use independently compiled Chialisp and native Rust where available. Never change a canonical module hash to hide incompatibility.
- Distinguish executed tests, bounded models, model-level proofs, and compiler-preservation proofs. Never claim absence of all security breaches.
- For each new puzzle: add Rust, original/reference source and provenance, positive and adversarial vectors, compiled artifacts/costs, and mutation controls when meaningful.
- The documentation site belongs in www, uses Astro + pnpm, and deploys with GitHub Pages. Build it around verified working examples and generated validation data.
- The owner made the repository public and authorized GitHub Pages publication. Preserve that visibility and deploy www through GitHub Actions.
- Use subagents for independent compiler, corpus, verification, or site tasks; coordinate ownership before editing shared files.
- Do not commit target, node_modules, build output, secrets, or temporary artifacts. Commit intentional reproducible reports.
- Before pushing Rust changes: cargo fmt --all --check; cargo test --workspace --locked; cargo clippy --workspace --all-targets --locked -- -D warnings.
- Run python3 scripts/check-proofs.py for proof/model changes. Run pnpm site checks/build when www changes.
- Push completed, verified work to origin; inspect CI and fix failures. Record remaining substantive work for continuation.
- When finding a Rue bug, search upstream issues first, then file or update an xch-dev/rue issue with pinned revision, minimal repro, observed/expected behavior, and a patch containing a failing regression test plus fix. Link local patches to the issue. The user explicitly authorized upstream bug reports; no extra confirmation is needed.
- Regenerate corpus evidence only after formatting Rust sources: build workspace, run `target/debug/chialisp-oxide validate --output corpus/validation.json`, then `python3 scripts/check-ir-proofs.py --output corpus/proofs.json`. The site rejects stale source/manifests/proof hashes.
- Keep Pages publication gated on successful compiler verification for the exact main commit, and verify the live evidence endpoint after deployment.

- Keep the landing page and README prominent about WIP prototype status and not ready for use. Do not market current tests or model checks as production readiness.
- Prefer researched Rust/Cargo authoring conventions. Do not present the standalone-file harness as the final user workflow or invent a rustc CLVM target before a real backend supports it.
- Lead new authoring examples with normal Cargo libraries, chialisp-oxide, and annotated exports. Keep native `cargo check/test` and the additional CLVM subset check distinct. Preserve Cargo's features, build scripts, generated code, and compiler arguments.
- Keep compiler-private integration on a tested dated nightly with matching components; do not restore RUSTC_BOOTSTRAP as a supported stable-toolchain workaround.
- Cross-crate lowering currently admits only structurally validated chialisp-oxide types/helpers. Do not broaden external calls until overflow flags, dependency MIR, generics, and trait resolution have explicit semantics and regression tests. Cargo integration tests must compare exact outputs, not acceptance alone.
- Write puzzle logic with named condition constructors, nominal domain types, explicit amount/time units, and named policy constants. Keep fixture key bytes in named supporting data. Retain ordinary Rust arithmetic and assertions; raw opcode tuples belong in SDK internals and independent wire-format tests.
- The paired corpus is the real `chialisp-oxide-puzzles` Cargo library. Validate annotated Cargo exports and link that same library for native execution; do not compile copied policies or silently route corpus checks through the standalone research driver. Maintain `puzzles/authoring.json` and fail on stale declared native/compiler inputs.
- Preserve canonical tutorial source exactly when porting examples. Record finite Rust integer bounds, exact ABI differences, and module-hash incompatibilities explicitly; a wrapper that changes the original's accepted inputs is an adapter, not the unchanged canonical program.
- Keep the default exact typed environment ABI. Only genuinely nullary exports may opt into `#[chialisp_oxide::puzzle(environment = "ignored")]`; carry that policy in the versioned IR envelope so legacy readers fail rather than silently changing accepted inputs.
- Compile canonical raw expressions with `chialisp_oxide_reference::compile_expression`, and modules with `compile`. The module API can evaluate a raw expression during compilation; executing that result again would compare the wrong program. Bind canonical example promotions to pinned source extraction and executed evidence, and keep whole-page completion separate.
- Compare actual Chialisp, Rust, and Rue source plus separately compiled artifacts. Rust using Rue LIR is not execution of a Rue source port. Preserve each language's measured semantics and record any adapter contract.
- Back “Errors that Rust makes impossible” with an executable limited Chialisp test suite, a missed counterexample, and a captured compiler/checker diagnostic. Keep native Rust errors, project subset checks, runtime checks, and model proofs distinct; credit equivalent Rue checks and show policy errors that still compile.
- Track concrete published puzzle sources with pinned repository trees, source identity, language, license, and search scope. A source catalog is discovery evidence, not a claim of completed ports. Do not present host Rust puzzle builders as on-chain Rust frontend support.
- Raw-tree exports use an explicit whole-environment ABI and exactly one logical Tree parameter, in the version-3 legacy envelope or version-4 runtime envelope. Preserve atom bytes and improper tails; do not accidentally decode it as a single-element argument list. Default strict decoding and ignored nullary policies retain their contracts in every supported version.
- The borrowed Tree exception admits structurally checked immutable Atom/Pair representations and lifetime-only helpers, not arbitrary enums/references/generics. Lower actual helper/promoted-constant MIR; never grant behavior based on an SDK name. Test adversarial same-name SDK bodies and layouts. Compile-time constant lowering remains acyclic even when source runtime calls recurse.
- Program factories are separate from condition-producing coin puzzles. Test their returned program in a second VM execution, record exact canonical source/license/artifact provenance and module identity, and never count factory tests as complete spends. Structural tree-model proofs remain separate from scalar models and compiler preservation.
- Rust optimization on runs the owned typed-IR guard pass, runtime frame elision, then Rue LIR optimization; off skips all three. Frame elision applies only to runtime lowering. Preserve required projection failures and strict/lazy evaluation. Model equivalence of one actual rewrite is not a universal optimizer proof. Runtime programs keep the guard pass unchanged: a projection after a diverging call cannot preserve an earlier guard's immediate rejection. Forward only total leaves, resolve slot identities in the final scope, and retain non-leaf atom-extraction bindings because the guard and result both consume the value. Tail identity lets still evaluate their initializer once in the outer scope. Bound pending operands and direct-lowering depth before descending. See docs/runtime-calls.md and scripts/check-runtime-frames.py.
- Coordinate Cargo phases: finish builds before driver extraction, proof/error-study regeneration, or workspace integration tests. Do not concurrently rebuild the shared driver while another process executes it. Finish source edits and formatting before recording implementation hashes.
- Use typed VM failure codes: resource/infrastructure failures are inconclusive and cannot confirm program rejection, including in boolean test helpers and serialized evidence. Ledger negatives must match the intended typed consensus code and preserve state; SDK signer preflight is not consensus rejection. Submit actual invalid-signature bundles and keep both VM versions/protocols explicit. Count grouped ledger scenario runs separately from transaction attempts.
- Recursive source graphs use version-4 function tables and strict lexical bindings. Preserve existing acyclic artifacts and reject runtime nodes in legacy wire formats. Callees have fresh scopes; arguments and unused initializers evaluate once in source order. Bound runtime frame/work growth before cloning or recursive lowering. Current proof models reject all runtime IR, and pair-guard rewrites remain disabled there until divergence-aware reasoning is implemented.
- Recognize compiler panic operations by actual rustc language/diagnostic item identity, never display paths or symbol spelling. Ordinary local or SDK functions named like core panic helpers retain their real bodies and results.
- Empty-slice patterns admit only the validated compiler-generated immutable byte-slice metadata chain. Keep pointer/`usize` temporaries internal, check every definition/use and charge scans before allocating or cloning. Preserve the captured atom at its source statement; nonempty zero bytes are never nil. General lengths, positive-length patterns and user pointers need separate reviewed semantics.
- Published include helpers need visible module adapters, exact source-span/license/commit/tree provenance and independent expected outcomes. Keep `canonical_helper_port` separate from unchanged canonical modules, original teaching fixtures, whole-library completion and module-hash claims. Run `scripts/check-canonical-helpers.py` and its mutation controls when changing that evidence.
- Build search through the local Pagefind `getFiles` adapter with awaited Node writes before closing the service. The pinned native `writeFiles` path can acknowledge unfinished disk writes; do not replace this with sleeps/retries or restore Starlight's affected writer. Preserve the stock search UI, reject empty assets, and run the actual built Pagefind query gate.

- Owned trees use the optional facade `alloc` feature (default off) and an injective Atom/Pair(Box<Self>, Box<Self>) shape. Recognize actual standard Box/Global/constructor/destructor identities, preserve original MIR types, validate closed metadata uses, and capture logical values outside ordinary pointer locals. Reject explicit global allocators visible in the crate graph, custom Drop, borrowed-pointee Boxes and unsupported pointer/Box APIs. Preserve strict initializers and snapshot semantics across moves/reassignment.
- Before native owned-tree construction, preflight the complete environment, including both children, aggregate expanded node/byte counts, and possible output depth. Keep resource/codec errors outside the policy-panic adapter. Consume output nodes iteratively even on encoding errors; host bounds do not become compiled policy guards or rejection evidence.
- Lean theorem gates must check fixed expected statement types and exact axiom dependencies, with algorithm/type/protocol corruption controls. Preserve the distinction between manual algorithm theorems, finite execution bridges, independent checker validation and compiler-preservation proofs. Run experiments/tree-theorems/check-model.py with pinned Lean and actual VM replays when changing these models or their bridge.

- Primitive byte equality must resolve actual core PartialEq diagnostic/trait/implementation identities and concrete primitive Self/Rhs types before logical type erasure. Never infer arbitrary `ne` as negated `eq`, trust display names, or cache totality by a generic trait DefId. Keep custom/mixed/mutable/non-u8 comparisons closed; test strict operands, nil/padding, actual standard refs/arrays and misleading overrides. Preserve reviewed existing corpus observations when adding a new helper.
- Source-derived proofs must extract fresh declared Cargo exports, check compiler/driver/source identities and requested modes, and retain exact IR/query/CLVM bytes. Specify acceptance independently over the complete environment; preserve projection definedness and require nonvacuity outside the source body's success domain. Replay distinguishing witnesses through actual native source and every claimed language mode, and execute retained modeled artifacts separately from internal recompilation. Label constructed IR controls separately from actual source mutations and credit ordinary compiler/Clippy checks. Keep installed compiler/standard-library assumptions visible; bundle freshness is not binary authentication or compiler preservation. Run scripts/test_cargo_bundle.py and scripts/check-byte-proofs.py with executed proofs plus evidence corruption controls when changing this layer.
- Enforce the pinned host/sysroot contract in early target preflight and actual parsed callbacks, then validate the bounded frozen loaded-crate graph before both IR export and metadata-only continuation. Check all core/alloc/std and primitive language/diagnostic owners, aliases, transitive dependencies and all CrateSource fields against real canonical installed paths. Preserve rustc response-file semantics by routing an expanded copy and compiling original argv; keep parsed crate/target identity checks and the mutable-build-input assumption. Some print modes compile and some probes load a backend before Config; test actual native behavior, final repeated option state and early sysroot/target/backend rejection. Native-valid relocation controls must prove their copied libraries were actually loaded; native deduplication back to pinned files is a positive control. Location policy is not installed-byte authentication or a host/plugin sandbox. Include compiler/native build scripts in implementation source hashes.
